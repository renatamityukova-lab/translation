# Отчёт о тестировании сервиса Transtalion

Проверка выполнена 24.11.2026 на локальном сервисе (`uvicorn`, порт `8000`).
Модель — `gpt-oss-120b`, резервная — `MiniMax-M2.7` (шлюз `https://llm.enplus.group/v1`).
Автотесты: `75 passed` за 3.35 с (`python -m pytest -q`).

## 1. Обычный перевод

Запрос `POST /chat` с идентификатором `ДоговорыКонтрагентов`:

```json
{"message": "ДоговорыКонтрагентов", "translated": "partner_contract"}
```

`HTTP 200`, время ответа — **1.18 с** (реальный вызов LLM).

## 2. Повторный запрос — ответ из кеша

Тот же идентификатор запрошен повторно:

```json
{"message": "ДоговорыКонтрагентов", "translated": "partner_contract"}
```

`HTTP 200`, время ответа — **0.028 с** (в 40 раз быстрее). Повторного обращения к модели нет:
в логе — `Кеш: попадание — 'ДоговорыКонтрагентов' → 'partner_contract'`.

## 3. Неверный ввод — понятное сообщение об ошибке

Пустая строка (или строка из пробелов) в `message`:

```json
{"detail": "Некорректный запрос — message: не должно быть пустым",
 "errors": [{"field": "message", "message": "не должно быть пустым"}]}
```

`HTTP 400`. Аналогично обрабатываются нестроковое значение
(`message: должно быть строкой`), лишнее поле (`extra: лишнее поле не допускается`)
и превышение длины 1000 символов.

## 4. Модель недоступна — понятное пояснение

Обе модели направлены на заведомо неработающий адрес (`http://127.0.0.1:9/v1`):

```json
{"detail": "Сервис перевода временно недоступен: Все модели недоступны — gpt-oss-120b:
 недоступна после 3 попыток (сетевая ошибка (ConnectError)); MiniMax-M2.7:
 недоступна после 3 попыток (сетевая ошибка (ConnectError))"}
```

`HTTP 503`, время — 19.15 с (ретраи с паузами, затем отказ). Клиент получает причину,
внутренние детали и ключ в ответ не попадают.

## 5. Отказ основной модели — автоматический переход на резервную

Основная модель недоступна, резервная (`MiniMax-M2.7`) работает:

```json
{"message": "ЗаказыПокупателей", "translated": "customer_order"}
```

`HTTP 200`, время — 10.97 с. Сервис продолжил работу без вмешательства: в логе
зафиксированы неудачные попытки основной модели и переключение на резервную.

## 6. «Грязный» ответ модели — нормализация

Модель вернула ответ с markdown и лишними пробелами:

```
"  **Partner   Contract**  "  →  partner_contract
```

Также отбрасываются блоки рассуждений reasoning-моделей
(`thinkingразмышления` + `warehouse_stock` → `warehouse_stock`) и пояснения
после перевода (`partner_contract\n\nПояснение модели` → `partner_contract`).

## 7. Пустой или невалидный ответ модели — 502

Если модель вернула пустой текст или не `snake_case`:

```json
{"detail": "Некорректный ответ модели: пустой ответ"}
```

`HTTP 502`. Результат не кешируется — следующий запрос снова идёт в модель.

## 8. Кеш: срок жизни и ограничение размера

Проверено детерминированно (подменяемые часы): запись с TTL 10 с доступна через 9 с
и исчезает через 10 с; при `max_size = 2` добавление третьей записи вытесняет
самую старую. Просроченные записи удаляются при обращении.

## 9. Служебная проверка и трассировка

`GET /health` → `HTTP 200`, `{"status": "ok"}`.

Каждый запрос получает `request_id`, который попадает во все записи лога
(консоль + `logs/transtalion.log` с ротацией) и в заголовок `X-Request-ID`.
Пример записи:

```
2026-11-24 14:01:20 | INFO     | ef83ea92 | services.translator | Кеш: попадание — 'ДоговорыКонтрагентов' → 'partner_contract' (0.000 с)
```
